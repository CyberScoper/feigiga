# Алгоритм отладки под таймер

## 0. Перед тем как кодить

- **Прочитай условие два раза.** Второй раз — выписывая вход/выход/ограничения.
- **Воспроизведи баг руками.** Если не можешь — задача не "почини баг", а "пойми, в чём он".
- **Минимальный пример.** Сократи входные данные до самого маленького, на котором баг ещё есть.

## 1. Где сломалось

Если есть стектрейс — читай **снизу вверх** до первого своего файла. Это место, где твой код встретился с реальностью.

Если стектрейса нет:
- `print/log` в трёх точках: вход функции, середина, выход. Это в 80% случаев находит баг быстрее, чем дебаггер.
- Бинарный поиск по логам: что было последним правильным значением?

## 2. Типовые подставы

| Симптом                                  | Где смотреть                                   |
|------------------------------------------|------------------------------------------------|
| `undefined`/`None` где не ждали          | необработанная пустая ветка, опциональное поле |
| Off-by-one                               | граница цикла, slicing `[0:n]` vs `[1:n+1]`    |
| Сравнения "не работают"                  | типы: `"1" == 1` ложно во многих языках        |
| Async странности                         | забытый `await`, race condition                |
| API возвращает не то                     | headers (Accept, Content-Type), кодировка      |
| Числа "не сходятся"                      | float precision, locale (запятая vs точка)     |
| Регулярка ловит лишнее                   | жадность по умолчанию, добавь `?`              |
| JSON не парсится                         | BOM, trailing comma, lone newlines             |
| Файл "пустой"                            | encoding, читал бинарь как текст               |
| Тест проходит локально, ломается в CI    | время / часовой пояс / порядок словарей        |

## 3. Если совсем застрял (>10 мин)

- **Объясни задачу AI как человеку.** В 30% случаев на формулировке "ой, тут же..."
- **Поменяй угол.** Перепиши кусок с нуля, не правя старый — часто быстрее.
- **Срежь скоуп.** Что из задачи можно НЕ решать, чтобы остальное заработало?

## 4. Anti-patterns

- "Это, наверное, баг библиотеки." → почти всегда нет.
- Менять рандомно строки, надеясь "вдруг заработает". → стоп, сядь и подумай.
- Уйти в рефакторинг при сломанном тесте. → сначала почини, потом причёсывай.
